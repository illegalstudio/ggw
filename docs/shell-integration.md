# Shell Integration

## Quick Setup

`ggw cd` needs a shell wrapper because a subprocess cannot change the parent shell's current directory.

Add one of these lines to your shell config:

```bash
# Bash, in ~/.bashrc
eval "$(ggw shell-init bash)"

# Zsh, in ~/.zshrc
eval "$(ggw shell-init zsh)"
```

For Fish:

```fish
# In ~/.config/fish/config.fish
ggw shell-init fish | source
```

Reload your shell after editing the config.

## Usage

After setup, use `ggw cd` normally:

```bash
ggw cd feature/login
ggw cd feature-login
ggw cd
```

The wrapper intercepts only `ggw cd`. Every other subcommand is passed through to the binary unchanged.

## Completion

`ggw shell-init` also emits shell completion code generated by Cobra.

Completion includes:

- command names, for example `ggw de<TAB>` completing to `delete`;
- branch names for worktree commands, for example `feature/login`;
- custom worktree directory names when they do not simply duplicate the branch slug.

Generated directory slugs such as `feature-login` are not suggested when the branch name is already `feature/login`.

## Without The Wrapper

Without shell integration, `ggw cd <name>` prints the target path to stdout:

```bash
cd "$(ggw cd feature/login)"
```

This mode is useful in scripts and for inspecting the resolved path.
